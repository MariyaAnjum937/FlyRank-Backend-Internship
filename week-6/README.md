# Week 6 — AI Support Message Classification API

A small backend API that uses an AI model to classify customer support messages into a fixed set of categories.

## What it does

The API accepts a support message and asks an AI model to classify it.

It returns:

- `category`: `billing`, `bug`, `feature`, or `other`
- `urgency`: `low`, `normal`, or `high`
- `confidence`: number between `0` and `1`
- `reason`: short explanation

If the AI is unsure, it should return `other` with low confidence.

## Example

### Request

```http
POST /classify
Content-Type: application/json
````

```json
{
  "text": "My payment was charged twice"
}
```

### Response

```json
{
  "category": "billing",
  "urgency": "high",
  "confidence": 0.95,
  "reason": "Customer was charged twice for a payment."
}
```

The exact confidence and reason may vary because the response is generated by the AI model.

## Reliability

The API does not blindly trust the AI response.

### Input validation

The request is validated using Zod.

The `text` field must:

* be a string
* contain at least 1 character
* contain at most 2000 characters

Invalid input returns HTTP `400`.

### Output validation

The AI response is:

1. Parsed as JSON
2. Validated against a Zod schema
3. Rejected if it contains an invalid category, urgency, confidence, or structure

This prevents unexpected AI output from being returned as a valid API response.

### Timeout

AI requests have a 5-second timeout.

### Bounded retries

Temporary failures such as timeouts, rate limits, and server errors are retried up to 3 attempts.

Retries use increasing delays between attempts.

## AI Provider

This project uses OpenRouter through the OpenAI-compatible API.

The API key is stored in `.env` and is not committed to Git.

Environment variables:

```text
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_API_KEY=
LLM_MODEL=openrouter/free
```

See `.env.example` for the required configuration.

## Installation

Clone the repository and install dependencies:

```bash
npm install
```

Create a `.env` file using `.env.example`:

```text
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_API_KEY=your_api_key_here
LLM_MODEL=openrouter/free
```

Do not commit the `.env` file.

## Run the API

```bash
node src/server.js
```

The server runs on:

```text
http://localhost:3000
```

## Test the API

Example using PowerShell:

```powershell
Invoke-RestMethod `
  -Uri http://localhost:3000/classify `
  -Method POST `
  -ContentType "application/json" `
  -Body '{"text":"My payment was charged twice"}'
```

## Run Tests

Run the automated test suite with:

```bash
npm test
```

The project contains 8 tests covering:

1. Valid billing classification
2. Valid feature classification
3. Invalid AI category
4. Malformed AI JSON
5. Uncertain classification
6. Invalid confidence value
7. Retry after temporary failure
8. Maximum retry limit

All 8 tests pass.

## Design Goal

The goal of this project is not to build a chatbot.

It demonstrates how to use an AI model as a small, controlled backend component where:

* inputs are validated
* AI output is treated as untrusted
* output is schema-validated
* requests have timeouts
* transient failures have bounded retries
* automated tests verify the important behavior
